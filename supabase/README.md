# Best Homz — Supabase

## Apply migrations

The BestHomz project uses ordered SQL migrations in this directory. On a fresh project, apply every migration in timestamp order:

1. `migrations/001_initial_schema.sql`
2. `migrations/002_indexes.sql`
3. `migrations/003_rls.sql`
4. `migrations/004_storage.sql`
5. `migrations/005_seed_categories.sql`
6. `migrations/007_seed_rooms_collections.sql` (rooms and collections)
7. `migrations/008_phase7_notes_and_cart_unique.sql`
8. `migrations/009_phase8_guest_quote_claim.sql`
9. `migrations/010_phase9_commerce.sql`
10. `migrations/011_ecommerce_upgrade.sql`
11. `migrations/012_security_hardening.sql`

For an existing project, check the migration history first and apply only pending migrations. Do not replay the initial schema over an existing database.

## Environment

Copy the root `.env.example` to `.env.local` and fill in the values from **Supabase Dashboard → Project Settings → API Keys**.

- `NEXT_PUBLIC_SUPABASE_URL`: project API URL.
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: the app's current variable name for the publishable key. A Supabase publishable key is safe to use in the browser when RLS is correctly enabled.
- `SUPABASE_SERVICE_ROLE_KEY`: server-only secret used by trusted server scripts/actions. Never expose it through a `NEXT_PUBLIC_*` variable or commit its value.

The frontend uses `@supabase/ssr` in `lib/supabase/client.js`, `server.js`, and `middleware.js`. The admin client in `lib/supabase/admin.js` requires the server-only service-role key.

## Phase 5 product import

After reconciling the live gallery (`npm run catalog:reconcile`):

1. `npm run catalog:validate`
2. Configure `.env.local` (see `.env.example`)
3. Review `data/products-import.json` and run `npm run catalog:import`.

The importer upserts products by slug and replaces each imported product's image, feature, and specification child rows. It also marks active products missing from the import file as inactive. Review the dataset and existing catalogue before running it against a populated project.

## Notes

- **Quote numbers** are generated by trigger (`BH-Q-YYYY-######`).
- **Pricing** lives in `product_pricing`; customer UI uses `config/pricing.js` (`SHOW_PRICES`).
- **Guest carts** use server actions + `SUPABASE_SERVICE_ROLE_KEY` and httpOnly `bh_cart_session` cookie (see `docs/phase7.md`).
- First **admin** user: sign up, then set `profiles.role = 'admin'` for that `auth.users.id` using a trusted administrator workflow.
- The two `is_staff()` and `is_admin()` SECURITY DEFINER helpers remain executable by authenticated users because RLS policies call them. Review any future changes to these helpers carefully.
